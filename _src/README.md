# Генератор на статиите

Тази папка **не се публикува**. GitHub Pages (Jekyll) пропуска всяка папка,
чието име започва с долна черта, затова `_src/` остава само в хранилището.

## Файлове

| Файл | За какво е |
|---|---|
| `build.py` | Сглобява готовия HTML от модул `articleN.py` + CSS + JSON-LD схемите |
| `articleN.py` | Съдържанието на една статия: заглавие, описание, ключови думи, снимки, увод, текст, FAQ, свързани статии |
| `sync_modules.py` | Обратното: пресъздава модулите от публикувания HTML |
| `modules.json` | Кой модул на коя статия отговаря |
| `style_base.css`, `extra.css` | Стиловете, които се вграждат във всяка страница |
| `unused/` | Модули без съответна публикувана статия |

## Правилото

**Публикуваният HTML е истината.**

Ако някоя статия бъде поправена директно във файла ѝ (а това се случва —
бърза корекция по живия сайт), модулът остава в старата версия. Следващото
пускане на `build.py` по тази статия мълчаливо връща старото съдържание.

Това вече се е случвало: връщаха се имена на машини в статията за BMW M8 и
отхвърлен абзац в статията за цената на автоключ.

Затова:

1. Промяна по статия — **първо в модула**, после `build.py`.
2. Ако все пак HTML-ът е пипан директно — преди следващ `build.py` се пуска
   `sync_modules.py`, за да се изравнят модулите.
3. След всяко пускане на `build.py` се сравнява видимият текст със
   `git diff`, преди да се качи.

## Пускане

```bash
# редактирай _src/articleN.py, после:
python3 _src/build.py          # списъкът със статии е в края на файла

# ако HTML е пипан директно:
python3 _src/sync_modules.py "$(cat _src/modules.json)"
```
